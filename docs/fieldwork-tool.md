# 调研数据工具使用说明（P0 数据管道）

本工具用于把《如果周六由你开校门》从"课堂原型"推进到"可带出现场"的阶段：它先解决**收数据、存数据、出结论**三件事，让人带着它去访谈和观察，回来当天就能得到结论。工具本身不新增任何制度功能，也不改变四分钟主流程。

## 一、为什么需要它

原报告第 12 页的"至少 80% 测试者能说出开放区 / 受限区 / 求助方式"和第 13 页的学生 8、公众 8、校方 2、城市 2 共 20 人访谈与现场观察，都还是**计划**。原型上线时零真实用户数据，所有制度参数仍是"拟议"。本工具把这三项数据的录入、统计、判定和导出做成固定管道，避免现场回来后再手工拼表、或把个位数条数的观察写成已经实现的成效。

## 二、三类记录

### 1. 理解测试（对应第 12 页 80% 门槛）

每位测试者一条记录：所属群体、测试任务（电子意见 / 纸卡 / 现场观察 / 结果卡）、以及能否**自主说出**下面三项：

| 编码 | 含义 |
| --- | --- |
| `open-zone` | 开放区（哪里可以自由参观） |
| `restricted-zone` | 受限区（哪里需要预约或不能进入） |
| `help-channel` | 求助方式（找谁、怎么求助） |

门槛口径固定在代码里（`src/fieldwork.ts`）：

- `TARGET_COMPREHENSION = 0.8`；
- `MIN_COMPREHENSION_SAMPLE = 8`：样本少于 8 人时判定为 `insufficient-n`，输出"样本不足，暂不判定"，**不写达标**；
- 三项各自必须 ≥ 80%，且三项全会（`allThree`）也必须 ≥ 80%，才算 `meets-target`；任一项不足即 `below-target`。

### 2. 现场观察（对应第 13 页四周现场观察）

每条记录：编号、日期、时段（`morning` / `noon` / `afternoon` / `evening`）、区域（`gate` 校门 / `hall` 展馆 / `sports` 运动区 / `route` 公共路线 / `service-desk` 服务台）、人流三档（低 / 中 / 高）、冲突描述，可选天气与排队分钟数。汇总给出各区域 × 时段的覆盖矩阵，用于检查"每个区域至少被看过几次"。

### 3. 访谈（对应第 13 页 20 人配额）

每条记录：编号、群体（student / public / staff / city）、时长、**原话引语**（至少一条）、预定义编码（至少一个）、态度（支持 / 有条件支持 / 反对 / 说不清）。

编码表不允许事后新增（`CODEBOOK`）：`access`（通行与可达）、`cost`（成本与承担者）、`fairness`（公平与名额）、`trust`（信任与信息处理）、`feasibility`（可执行性）。这样不同访谈者回来后的口径一致，统计才可比。

配额缺口按 `QUOTA = student 8 / public 8 / staff 2 / city 2` 计算实际人数与缺口。

### 4. 需求结论的判定口径

`demandStatus(code, records)`：

| 条件 | 结论 |
| --- | --- |
| n = 0 | `proposed`（拟议） |
| 1 ≤ n < 3 | `mixed`（条数不足，不允许写成支持） |
| n ≥ 3 且同向 ≥ 2/3 | `supported`（有现场支持） |
| n ≥ 3 但同向不足 2/3 | `mixed`（分歧） |
| 全部反向 | `rejected`（被现场否定） |

> 清单只要求"少于三条不能写成 supported"；本实现把 1–2 条统一归为 `mixed`，宁可少说也不拔高。

**非拟议结论必须带原话引语**：任何不是 `proposed` 的结论都附上支撑它的访谈引语，否则报告里不出现该结论。这条在 `tests/fieldwork.test.ts` 里有专门用例守住。

## 三、怎么在现场用

1. 打开 `git` 工作区里的页面，进入任一课程页面 →「回看本次推演与课程结论」→ 面板底部「调研工具：录入与统计」。这是唯一入口，它**追加在主流程之后**，不影响原有按钮顺序。
2. 手机 / 平板 / 笔记本均可：录入界面用原生 input / select / textarea，一屏一项，走原生输入法，不依赖 A-Frame 场景。
3. 每录完一条立即落盘到 `localStorage`（键名 `saturday-campus-v1` 的 `fieldwork` 字段），刷新、锁屏、换设备都不会丢。
4. 当天结束：点「导出全部调研 JSON」，复制整段文本存档（可发到群里或存进网盘）。
5. 回到教室：在另一台设备点「导入调研 JSON」→ 弹出输入框 → 粘贴整段文本 → 点「导入并替换当前记录」。工具会校验版本和记录与统计是否自洽，非法内容回到初始状态而不会污染已有记录。
6. 点「查看统计与覆盖缺口」进入「调研统计：数据与结论分开」页，给出：理解测试判定、观察覆盖矩阵、访谈配额缺口、各编码需求结论与引语。

## 四、课程复盘如何读取现场数据

`courseReview(state, prototypes?, fieldwork?)` 的第三个参数**可选**：

- **不传**时，行为与提交 `08bcd12` 逐字段等价（`tests/fieldwork.test.ts` 里用空的、已选规则、已领卡等多种状态守住）。
- 传入时，所有条目新增 `evidenceLevel`（`none` / `classroom` / `field`），但 `status` 仍只有原来的三种取值——**现场数据只提升证据等级，不改变制度结论是"拟议"这一事实**。
- 当 `rules` 或 `resources` 有 ≥ 3 条对应编码的实地访谈时，对应条目升为 `field`，文字里明确写"这只说明已有现场证据，不代表制度落地"。
- 「访谈、现场观察与实际成效」条目显示 `实地：访谈 n/20，观察 m 条，理解测试 k 条`，样本不足时追加"样本不足暂不判定"。
- 复盘摘要追加"已收集 N 条现场记录，制度落地仍待确认"，且不出现任何把拟议写成既成事实的措辞。

## 五、隐私与边界

- 只保存匿名编号，不收集姓名、照片、学号、手机号；界面上没有对应字段。
- 数据全部在浏览器本地，无任何网络请求（离线可用，外网请求为 0）。
- 工具不替代正式调研伦理流程：现场仍需口头说明用途、征得同意、允许随时退出。
- 数据条数未达阈值时，报告与复盘都不会输出达标结论；阈值达标也只表示"这一轮样本达到门槛"，不表示制度已落地。

## 六、相关文件

- `src/fieldwork.ts`：数据模型、统计、判定、事件重放、导入导出。
- `src/fieldwork-ui.ts`：录入面板、统计面板、抽屉表单。
- `src/course.ts`：`courseReview` 第三参数与 `evidenceLevel`。
- `src/main.ts`：`fieldwork:*` 动作分发与本地持久化。
- `tests/fieldwork.test.ts`：18 条用例，覆盖判定口径、配额、导入导出、重放与向后兼容。
