测试日期：2026-11-19（Asia/Shanghai）。环境为本机 macOS、Codex 随附 Node 24、pnpm 11.25.0、系统 Google Chrome 157.0.8103.79 + Playwright。浏览器使用 headless Chrome 真正创建 WebGL 场景，并以 SwiftShader 渲染；不是静态 DOM 截图，也没有用触发业务 dispatch 冒充三维点选。

- `pnpm test`：**26/26 通过**，包括12项原业务、7项制度原型、7项课程对应测试。

- 名额与人物去向：两政策均 12 公众席 + 8 学生席；A↔B 正反向都是 4 得 4 失 8 同。B 场景除独立重放的 O01/O02 外，10 人到展馆、4 人到公共展台，均读取同一分配结果。

## 本轮发现并修复的问题

1. UI 每次刷新重置 setLayout，导致重放刚开始就被取消：改为相同布局幂等更新。
2. A-Frame 的 remove() 在元素已经移除后再次调用会抛异常，导致 v2 刷新无法完成初始化：移除重复删除，改为只清理当前实际子元素。
3. UI 与实际路径侧廊转弯点不一致：地图、重走和人物统一读取 LAYOUTS。
4. 自动路线未取消会在用户导航后继续移动：导航使路线令牌失效并恢复面板。
5. 头显错误和信息热点只出现在网页层：增加世界面板及头显内 Canvas 提示。
6. 手柄默认模型会请求 CDN：禁用外部模型，保留本地射线。
7. 房间尺度旋转和地点导航未补偿追踪偏移：绕头部脚点旋转、按目标脚点平移。
8. 遮挡墙可被 WASD 穿过：移动增加墙体边界排除。
